# 产品需求文档

## 1. 产品名称

暂定：**CS2 收藏品价格研究看板**

## 2. 用户与运行环境

- 第一阶段只有一名用户。
- 用户使用 Windows，编程基础为零。
- 应用通过桌面图标启动。
- 应用运行在用户电脑上，不使用付费服务器和付费数据库。
- 电脑每天约开机10小时；电脑休眠和关机期间可能缺失采集。
- 第一版仅允许本机访问。
- 未来可能增加多用户注册，但不属于当前架构验收范围。

## 3. 核心目标

把 CS2 收藏品按来源、时代、行动、地图、武器箱和供应状态建立完整分类体系，并展示其中目标饰品、武器箱、刀具和手套的价格历史、事件时间线与回撤指标。

产品重点是“按收藏品进行横向比较”，不是普通的单品搜索商城。

## 4. 数据对象范围

### 4.1 枪械饰品

- 收录所有官方收藏品和武器箱系列。
- 首页只展开显示其中存在隐秘级枪械饰品的系列。
- 目标枪皮只显示：
  - 普通版本
  - 非纪念品
  - 非 StatTrak
  - 崭新出厂
  - 略有磨损
- 每个磨损独立一行和独立K线。

示例顺序：

1. AK-47丨精灵之噬（蔓藤纹）—崭新出厂
2. AK-47丨精灵之噬（蔓藤纹）—略有磨损
3. AWP丨无上之焰（蔓藤纹）—崭新出厂
4. AWP丨无上之焰（蔓藤纹）—略有磨损

名称尽量与悠悠完全一致，括号中显示收藏品出处。

### 4.2 武器箱

武器箱本身是一级价格对象，需要展示：

- 当前最低在售价
- 当前最高求购价，仅辅助展示
- 数据记录期最高价、最低价和日期
- 回撤
- 7日、30日、90日变化
- 首次推出时间
- 当前供应状态
- 状态变化时间线
- 箱内隐秘级枪皮
- 对应刀具或手套特殊稀有池
- 事件前后24小时、7日、30日、90日价格变化
- 事件后最高涨幅和最大回撤
- 可用时的开箱量或开箱趋势

不要把所有状态简化为“下架”。必须使用真实状态，例如：

- 加入游戏
- 进入活跃掉落池
- 退出活跃掉落池
- 转入稀有掉落池
- 行动结束
- 停止直接产出
- 当前仍可产出
- 状态不确定

### 4.3 刀具和手套

- 跟随对应武器箱展开。
- 同一特殊稀有物品属于多个武器箱时，价格对象只保存一份。
- 每种刀型动态展示当前最贵的两个标准涂装。
- 每种手套型号动态展示当前最贵的两个标准配色。
- 磨损只看崭新出厂和略有磨损。
- 排名依据为当前最低在售价。
- 不考虑：
  - 宝石
  - 多普勒宝石变体
  - 特殊模板
  - 淬火模板
  - 特殊浮点
  - 贴纸溢价
  - 改名
  - 卖家描述中的人工溢价
- 非前两名候选仍持续采集，以便排名变化后保留历史。
- 排名代表磨损策略做成可配置项，原型默认使用崭新；崭新无有效价格时使用略磨，并在管理页可修改。

## 5. 首页信息架构

首页不能只分四类。必须先研究并建立完整的多维收藏品分类体系。

基本层级：

```text
来源分类
└── 收藏品或武器箱系列
    └── 隐秘级饰品、武器箱、刀具或手套
        └── 磨损
```

同一个收藏品允许出现在多个来源分类中。例如远古收藏品可同时出现在：

- 狂牙大行动系列
- 新版比赛地图系列
- Major地图收藏品

重复出现时：

- 价格数据只保存一份。
- 页面允许多处展示。
- 来源标签使用明显的大字号。
- 详情页展示完整身份变化时间线。

首页字段至少包括：

- 来源大类
- 收藏品出处
- 悠悠饰品名称
- 磨损
- 首次进入游戏日期
- 关键事件摘要
- 当前悠悠最低在售价
- 当前悠悠最高求购价
- 数据记录期最高价及日期
- 数据记录期最低价及日期
- 从最高点回撤
- 距最低点涨幅
- 7日、30日、90日变化
- 数据来源
- 更新时间
- 数据完整度

首页默认记住上一次展开状态。

## 6. 详情页

点击枪皮、刀具、手套或武器箱名称进入详情页。

必须支持：

- 1小时K线
- 4小时K线
- 日K线
- 周K线
- 时间缩放
- 数据源图例
- 数据完整度提示
- 历史事件竖线
- 同日多个事件合并为一根竖线
- 竖线顶部右侧显示摘要
- 点击事件线查看完整事件列表、公告时间、生效时间和来源
- 外部参考线开关
- 原始币种和价格口径说明
- 事件前后影响指标

主K线定义：

> 每个周期内，悠悠最低在售价的开盘价、最高价、最低价和收盘价。

禁止把实际成交价混入主K线。

## 7. 同武器比较页

点击武器类型，例如 AK-47，进入同武器比较页：

- 展示所有收藏品中的目标隐秘级饰品。
- 崭新与略磨分开比较。
- 当前最低售价。
- 数据记录期最高、最低和回撤。
- 7日、30日、90日变化。
- 收藏品来源标签。
- 当前供应状态。
- 允许把多条走势归一化到100进行相对涨跌比较。

## 8. 价格采集与刷新

- 后台原始采集频率：每15分钟。
- 首页展示刷新频率：每小时。
- 服务启动时先检查：
  - 网络
  - Token
  - IP白名单
  - 上次成功采集时间
  - 缺失区间
- 能从合法接口补回的缺口应补回。
- 无法补回的缺口必须留空。
- 不能用前后价格连线伪装连续数据。
- 不完整周期不用于计算新的历史最高或最低，除非管理页明确允许。

## 9. 桌面运行

双击桌面图标后：

1. 检查配置和Token。
2. 自动处理允许的IP白名单绑定。
3. 检查并补回缺失数据。
4. 启动本地采集服务。
5. 启动本地网页。
6. 自动打开浏览器。
7. 最小化到系统托盘。
8. 关闭浏览器或控制窗口后服务继续运行。
9. 只有托盘菜单“退出服务”才停止采集。

托盘菜单至少包含：

- 打开看板
- 立即同步
- 查看同步状态
- 查看缺失数据
- 设置
- 备份
- 查看日志
- 退出服务

## 10. 管理与人工修正

提供仅本机可用的管理页：

- 修改收藏品名称。
- 维护悠悠显示名称。
- 添加多个来源分类。
- 设置醒目来源标签。
- 调整分类和收藏品排序。
- 修改公告日和生效日。
- 添加来源链接和可信度。
- 隐藏错误、重复或不适用记录。
- 设置某收藏品在哪些分类重复展示。
- 修改刀具与手套排名磨损策略。
- 查看所有人工覆盖记录。
- 恢复为原始导入值。

原始数据和人工覆盖必须分表保存。

## 11. 通知

第一版不实际发送通知，但必须预留：

- 规则表
- 通知事件表
- 发送队列表
- Gmail渠道
- Discord渠道
- 触发时间
- 实际补发时间
- 去重键
- 关机期间触发后的补发状态

后续通知应由普通程序完成，不调用AI。

## 12. 非功能要求

- 电脑端优先。
- 本地服务仅监听 localhost。
- 页面在2万条以上表格记录时仍需流畅，采用虚拟滚动或分页。
- 导入和采集过程可恢复。
- 数据库损坏前有可恢复备份。
- 用户无需使用命令行完成日常启动。
- 所有错误信息面向非程序员，给出可执行的修复步骤。
