# 存储与备份

## 保留策略

- 15分钟快照：90天
- 1小时OHLC：2年
- 1日OHLC：永久
- 4小时：动态生成
- 1周：动态生成
- 事件：永久
- 分类：永久
- 人工覆盖：永久
- 外部历史：永久
- 日志：默认30天

## 空间目标

按约400至600个持续监控对象估算：

- 主数据库长期目标：约1GB至2.5GB
- 主数据库警告阈值：2.5GB
- 主数据库硬警告：3GB
- 自动备份总上限：2GB
- 日志和缓存目标：低于500MB

实际大小取决于：

- 监控对象数量
- 索引数量
- 原始响应是否保留
- 外部历史点数量
- SQLite页和碎片
- 备份压缩率

应用必须显示实际占用，不仅显示估算。

## 自动备份

- 每日首次成功采集后创建恢复点。
- 每周保留一个长期恢复点。
- 每月保留一个长期恢复点。
- 总量超过2GB时删除最旧且非锁定的备份。
- 备份完成后执行完整性检查。
- 定期恢复到临时数据库进行验证。
- 手动备份可由用户标记为“锁定”，但必须提示其不受2GB自动清理规则保护。

## 数据库维护

- SQLite WAL。
- 定期checkpoint。
- 删除过期快照后按需要执行增量vacuum。
- 所有清理前先创建可验证备份。
- 不在采集任务运行时执行大型vacuum。
